# 3. Cel i zakres pracy (черновик, RU)

## 3.1. Cel pracy

Главной целью работы является разработка и практическая валидация персонализированной мобильной системы планирования тренировок для платформы Android, которая — в отличие от статичных программ и простых журналов тренировок — самостоятельно адаптирует тренировочную нагрузку на основе фактических результатов пользователя. Реализация системы велась вокруг шести конкретных задач.

Первой задачей было создание мобильного приложения под Android с интуитивно понятным интерфейсом для планирования и отслеживания тренировок — базового рабочего инструмента, вокруг которого строятся все остальные функции.

Второй, ключевой в инженерном смысле задачей стало внедрение адаптивной системы изменения тренировочной нагрузки на основе реальных результатов выполнения упражнений. Именно этот алгоритм отвечает на вопрос, поставленный во введении: сколько веса добавить на следующей тренировке, опираясь не на интуицию пользователя, а на объективную историю его тренировок.

Третьей задачей было предоставление пользователям возможности выбирать между готовыми тренировочными программами в разных направлениях (силовой тренинг, армрестлинг, стритлифтинг и др.) либо создавать собственные планы — совместить удобство готовых решений с гибкостью полностью персонализированного подхода.

Четвёртой задачей стало внедрение системы ежедневного мониторинга состояния здоровья для комплексной оценки текущей формы пользователя — как дополнительного источника данных для рекомендаций, а не только истории тренировок.

Пятой задачей было обеспечение функции отслеживания прогресса, включая графики изменения весов, количества повторений и массы тела — превращение сырых данных тренировок в понятную пользователю аналитику.

Наконец, шестой задачей стало создание социальной функции «Друзья», позволяющей пользователям делиться своим прогрессом друг с другом и использовать социальную мотивацию как дополнительный фактор приверженности тренировкам.

## 3.2. Zakres pracy

Объём реализации охватывает как разработку клиентского мобильного приложения, так и создание сопутствующей серверной инфраструктуры и интеграцию внешних сервисов. На стороне клиента использован фреймворк Flutter (Dart) с управлением состоянием на основе пакета Provider — весь пользовательский интерфейс, бизнес-логика адаптивного алгоритма и локальное хранение данных (SharedPreferences) реализованы в рамках единого мобильного приложения. Серверная часть построена на платформе Firebase: Cloud Firestore используется для синхронизации профилей, статистики и социальных функций между устройствами, Firebase Authentication — для аутентификации пользователей, а Cloud Functions (Node.js) — для фоновых серверных задач, в частности регулярного обновления мировых рекордов Международной федерации пауэрлифтинга (IPF) из внешнего источника. Дополнительно система интегрирована с внешним API языковой модели Groq для генерации и оценки тренировочных планов с помощью искусственного интеллекта.

Разработка велась силами одного автора, единолично отвечавшего за проектирование архитектуры, реализацию клиентской и серверной логики, наполнение библиотеки упражнений и тренировочных программ, а также организацию процесса валидации.

Часть работы, посвящённая непосредственно эмпирической проверке системы, состояла в организации и проведении полугодового (декабрь – май) наблюдения за группой из пяти пользователей с различным уровнем тренировочного опыта, сборе их обратной связи и сопоставлении полученных результатов с четырьмя референсными приложениями (Strava, Hevy, Strong, JEFIT).

Помимо шести перечисленных выше задач, в процессе реализации функциональный объём системы был расширен — соответствующие модули (генерация планов с помощью ИИ, система рангов и достижений, таблица лидеров, модуль питания и др.) описаны отдельно в главе 7 как выходящие за рамки первоначально заявленной темы.
