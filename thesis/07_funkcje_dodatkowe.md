# 7. Funkcjonalności wykraczające poza podstawowy zakres pracy (черновик, RU)

В процессе реализации функциональный объём системы вышел за пределы шести официально заявленных целей. Ниже описаны наиболее значимые дополнительные модули — не как второстепенные, а как самостоятельная часть инженерного результата работы, требующая отдельного описания.

## 7.1. Generowanie planów treningowych z wykorzystaniem AI

Сервис `GroqService` (`lib/services/groq_service.dart`, 613 строк) интегрирует приложение с внешним API Groq — облачной платформой инференса больших языковых моделей, использующей специализированное аппаратное обеспечение (LPU) для сверхнизкой задержки ответа. В качестве модели используется `llama-3.3-70b-versatile`.

Для каждого из четырёх тренировочных направлений (Full Body, Powerlifting, Armwrestling, Streetlifting) определён детальный контекстный промпт, задающий приоритеты по мышечным группам и жёсткие правила отбора упражнений — например, для направления Powerlifting приседания, жим лёжа и становая тяга помечены как обязательные, если присутствуют в библиотеке упражнений пользователя. Результат генерации оборачивается в модель `AiSuggestedWorkout`, содержащую саму программу (`Workout`), текстовое обоснование выбора (`reasoning`) и метку времени генерации.

Важное проектное решение — AI не применяет план автоматически. Сгенерированная программа проходит через экран одобрения (`programs_screen.dart`), где пользователь может принять или отклонить предложение; при ошибке генерации (например, при недоступности сети или неверном ключе API) пользователю показывается явное сообщение об ошибке, а не тихий сбой. Таким образом реализована модель «человек в контуре» (human-in-the-loop) — искусственный интеллект выступает советчиком, а не автономным агентом, принимающим решения без контроля пользователя. Отдельный виджет `workout_ai_evaluation.dart` использует ту же модель для оценки уже выполненной тренировки.

## 7.2. System rankingowy i grywalizacja

Система прогрессии реализована в двух взаимодополняющих сервисах. `RankService` вычисляет ранг пользователя напрямую относительно мирового рекорда в конкретном упражнении (`calculateRank(userBest, worldRecord)`, `percentOfWorldRecord`, `kgToNextRank`) — семь уровней от «деревянного» (wooden) до «алмазного» (diamond), визуализированных соответствующими иконками (`assets/images/*_rank.png`).

Более сложный алгоритм реализован в `RankingAlgorithm` (`lib/services/ranking_service.dart`) — композитная оценка, объединяющая четыре взвешенных компонента: силу (`strength`, вес 0.45, вычисляется только при наличии достаточного числа отслеживаемых упражнений), консистентность тренировок (`consistency`, вес 0.20), достижения (`achievement`, вес 0.15) и текущую динамику (`momentum`, вес 0.20). Итоговый линейный балл дополнительно преобразуется степенной функцией `100 × (linear / 100)^1.35`, что делает верхние ранги непропорционально труднодостижимыми — эффект, аналогичный принципу прогрессивной перегрузки (раздел 4.1), перенесённый в игровую механику. Из композитного балла также вычисляется примерная перцентиль пользователя (степенная кривая с показателем 1.8) и коэффициент уверенности в оценке (`confidence`), растущий с объёмом накопленных данных — при недостатке истории система честно понижает уверенность и опирается на эвристику, а не выдаёт вводящий в заблуждение точный ранг. Каждое присвоение ранга сопровождается текстовым объяснением (`_buildReason`), в духе того же принципа интерпретируемости, что и в адаптивном алгоритме нагрузки (раздел 6.2).

Систему дополняют достижения (`achievement_popup_service.dart`) и челленджи (`ChallengeService`) — соревнования между пользователями (обычно друзьями) по одной из пяти категорий: число тренировок, суммарный поднятый вес, результат в конкретном упражнении, серия тренировок, консистентность выполнения плана. Челленджи транслируются в реальном времени через потоки Firestore (активные/завершённые/ожидающие подтверждения) и поддерживают принятие и отклонение приглашения.

## 7.3. Tablica liderów i porównanie ze światowymi rekordami IPF

Экран `community_leaderboard_screen.dart` предоставляет пять категорий рейтинга сообщества (число тренировок, суммарный вес, рекорд по выбранному упражнению, текущая серия, прогресс — в разработке), построенных на агрегированной коллекции `user_stats` в Firestore с учётом приватности (пользователь может скрыть себя из публичных рейтингов).

Уникальной особенностью системы является сопоставление результатов пользователя с реальными мировыми рекордами Международной федерации пауэрлифтинга (IPF). Serverless-функция в `functions/index.js` (Node.js, Firebase Cloud Functions v2, триггер по расписанию) обращается к открытому API портала openpowerlifting.org, последовательно запрашивая лучший результат по каждой комбинации пол × весовая категория × упражнение (приседание, жим лёжа, становая тяга) и сохраняя результат в Firestore. Эти данные затем используются `RankService` и экраном `stats_comparison_screen.dart` для отображения, например, «твой присед составляет 62 % от мирового рекорда в твоей весовой категории» — превращая абстрактный личный рекорд в объективно проверяемый показатель.

## 7.4. Moduł żywieniowy

`NutritionAlgorithmService.calculateTargets(...)` рассчитывает суточную норму калорий и макронутриентов на основе базового обмена веществ (BMR) по формуле Миффлина — Сан Жеора [ŹRÓDŁO: Mifflin M.D., St Jeor S.T. i wsp. — zweryfikować dokładne dane bibliograficzne przed użyciem]:

```
BMR (мужчины) = 10 × вес(кг) + 6.25 × рост(см) − 5 × возраст + 5
BMR (женщины) = 10 × вес(кг) + 6.25 × рост(см) − 5 × возраст − 161
```

Полученное значение BMR умножается на коэффициент активности, определяемый числом тренировочных дней в неделю (от 1.2 при отсутствии тренировок до 1.9 при семи тренировках в неделю), что даёт общий суточный расход энергии (TDEE), к которому добавляется поправка на цель пользователя (набор/удержание/снижение массы) в пределах безопасного диапазона (ограничено снизу и сверху — от 1200 до 6000 ккал). Из итогового значения калорий далее вычисляется распределение по белкам, жирам и углеводам (`MacroTargets`). Модуль представлен экранами `nutrition_screen.dart` и `nutrition_goal_screen.dart` и моделью `nutrition_profile.dart`.

## 7.5. Personalizacja, lokalizacja wielojęzyczna i onboarding

Приложение поддерживает три языка интерфейса — английский, польский и русский (`lib/l10n/app_en.arb`, `app_pl.arb`, `app_ru.arb`) через встроенный механизм локализации Flutter. Тема оформления настраивается пользователем через `ThemeService`/`AppColor` (реализация Provider поверх `ChangeNotifier`, аналогично остальным сервисам приложения). Для новых пользователей предусмотрен интерактивный обучающий тур (`TourService`, `tour_overlay.dart`), знакомящий с основными разделами приложения при первом запуске.
